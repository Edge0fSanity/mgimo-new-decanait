# 06 QA — Деканат · тесты и критерии выпуска

Версия 1.0 · 10 ноября 2026 · все сроки МСК.

# Статус

Продуктовые тесты НЕ ВЫПОЛНЯЛИСЬ; все D-Q имеют статус NOT RUN. Организация документов проверяется отдельно.

Запись результата: test\_id; дата/время; commit/релиз; среда/браузер/ширина/сеть; A/B; шаги; expected/actual; PASS/FAIL/BLOCKED/NOT RUN; evidence; проверяющий. Пароли в evidence не включать.

# Матрица обязательных проверок

D-Q01 \| D-R01 \| Войти A и B в отдельных сессиях. Проверить разные ФИО/факультет/направление/курс/группу, ошибочный пароль, выход и недействительность сессии после выхода. Без входа личные страницы и прямые запросы недоступны.

D-Q02 \| D-R02 \| Сегодня/неделя, смена дня, пустой день, преподаватель/аудитория; перенос заметен, прежние и новые данные согласованы с уведомлением. Данные A/B соответствуют их группе.

D-Q03 \| D-R03 \| Оценки, зачёты и сессия для двух студентов; статусы понятны без цвета, нет чужих записей и выдуманных расчётов.

D-Q04 \| D-R04/05 \| Подать справку и заявление; проверить валидацию, номер/дату/статус; обновить страницу, выйти/войти, перезапустить сервер — записи сохраняются. Изменить статус разрешённым способом, увидеть историю/результат; скачать образец с пометкой недействительности.

D-Q05 \| D-R06/07 \| Объявление, дедлайн, перенос и статус заявки; переходы ведут к правильным объектам; прочитано сохраняется отдельно A/B; общий контент намеренно общий.

D-Q06 \| изоляция \| Для профиля, оценок, заявки, документа/URL скачивания и личного уведомления заменить ID объекта A на B в URL и прямом запросе. Проверить GET, изменение, создание с подставным student\_id и удаление, если оно есть. Ожидается отказ 403/404 без чужих данных; без сессии — 401/редирект без утечки. Повторить B→A, включая списки/поиск/экспорт, если реализованы. Скрытая кнопка не считается защитой.

D-Q07 \| пароли/сессии/секреты \| Проверить, что БД содержит только адаптивные хеши с солью; пароль не появляется в логах, HTML, bundle, Git/истории и скриншотах. Проверить HTTPS/cookie, CSRF для изменений, ограничение неверных входов, валидацию/экранирование. Секреты сервиса не отдаются браузеру. Если добавлена роль сотрудника — отдельно проверить эскалацию привилегий.

D-Q08 \| мобильность/доступность \| На 360/390/768/1440 px пройти вход, расписание, оценки, заявку/статус, документ и уведомления. Нет горизонтального скролла страницы/перекрытий; читаемый текст, фокус и подписи полей, клавиатурная навигация, контраст; загрузка/пустота/ошибка и повторная попытка понятны.

D-Q09 \| эксплуатация \| Проверить миграции, повторный запуск без потери заявок, резервную копию и восстановление в отдельной среде. Повторный seed не стирает данные. Ошибка сети не создаёт ложный успех; повтор отправки не порождает незаметные дубли.

D-Q10 \| доступ из РФ \| В реальной сети РФ без VPN на телефоне и desktop открыть URL, войти, посмотреть данные, создать заявку и скачать файл. Зафиксировать дату, сеть/оператора, устройство и результат без персональных данных. Проверить зависимости/CDN/шрифты; доступ из среды агента недостаточен. Повторить перед подачей и ежедневно 23–28.11.

D-Q11 \| данные/маркировка/лицензии \| Все студенты/преподаватели/номера/документы фиктивны; нет интеграции с настоящим вузом; видна маркировка конкурса; официального логотипа нет; лицензии сторонних материалов перечислены.

D-Q12 \| комплект жюри \| Ссылка работает, два аккаунта с разными данными переданы капитану безопасно, код/архив доступен, процесс описан с инструментами/промптами/скриншотами/ошибками/ручными шагами. Если есть сотрудник — передан третий аккаунт. Видео при наличии ≤5 минут.

# Критерии выпуска

Все D-Q01…D-Q12 PASS на финальной версии; нет критических/высоких дефектов безопасности и блокирующих UX ошибок; тест из РФ подтверждён, назначен ответственный до итогов.

Функциональность нельзя доказать только скриншотом или unit-тестом. Изоляция требует негативных серверных запросов; сохранность — перезапуска; мобильность — прохождения действий; РФ — реальной сети.

После любой правки auth повторить матрицу изоляции, после UI — затронутые мобильные сценарии, после deploy — smoke и сохранность. Не перезапускать все проверки без причины, но финальный релиз проходит полный P0 набор.
