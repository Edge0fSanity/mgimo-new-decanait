10 AI\_TASKS — Деканат · выдаваемые задания AI-команде  
17.11.2026. Это шаблоны будущих поручений, а не доказательство выполненных запусков. Полные реальные prompts и выходы сохранять после фактической работы в evidence/prompts/ и PROMPT\_LOG.

Общий принцип  
Основной разработчик владеет схемой БД, маршрутами, интеграцией и merge. Аналитик/дизайнер/QA работают только на отдельных результатах или непересекающихся файлах. Никаких фоновых агентов без явного запуска. Для каждого задания: task\_id, основание D-R, входные docs, changed files, команды запуска, evidence, критерии PASS/FAIL и блокеры.

ЗАДАНИЕ A01 — ROOT / first vertical slice (P0, владелец: основной разработчик)  
Вход: README, PRD, AGENTS, ADR, ARCHITECTURE, QA, UI\_SPEC.  
Промпт для выдачи после создания репозитория:  
«Реализуй первую проверяемую вертикаль проекта “Цифровой деканат будущего”. Стек: Python 3.12, Django 5.2 LTS, Django Templates/CSS, SQLite, Argon2, серверные сессии. Открой существующие документы в docs/ и не переписывай их. Создай два полностью вымышленных студенческих аккаунта одной основной группы с разными языковыми группами, профилями и личным расписанием. Пароли не хардкодить и не логировать: только хеши, секреты через env. Реализуй вход/выход, профиль, страницы “Сегодня” и “Неделя”, создание справки, список/детали заявки с сохранением в БД после перезапуска. На всех queryset используй request.user и проверку доступа на сервере; URL чужой заявки и прямой запрос должны возвращать 404; студент не должен менять статус. Добавь Django migrations, idempotent seed без сброса существующих заявок и минимум интеграционные тесты A→B, B→A, неавторизованный 401/redirect, CSRF, неверный пароль, restart/persistence. Не добавляй калькулятор, кеш или кабинет сотрудника. Сначала покажи план файлов, затем реализуй, запусти тесты, зафиксируй реальные команды и результаты. Не объявляй deployment готовым без проверки.»  
Ожидаемые файлы: manage.py, config/, apps/accounts/, apps/academics/, apps/requests\_app/, templates/, static/, tests/, pyproject.toml/lock, .env.example, README.md.  
Критерии: оба аккаунта входят и видят разные пары; заявка A переживает logout/relogin и перезапуск; B получает 404 на заявку A; submit от B не может указать A владельцем; тестовый отчет и commit доступны.  
Нельзя считать закрытым на основании только успешно запущенного сервера.

ЗАДАНИЕ A02 — ядро образования и коммуникаций (P0, владелец: разработчик после A01)  
«На основе действующего Django-проекта добавь оценки/зачёты/сессию, две формы заявки (справка и заявление), статусы и историю, защищённый документ-образец, новости, дедлайны и уведомления с сохранением read\_at. Добавь ограниченный служебный интерфейс Django Admin без прав на оценки. Действие staff “готово/отклонено” создаёт аудит и уведомление студенту. Весь новый личный контент фильтровать по request.user; покрыть негативными тестами IDOR и прав на каждый объект. Не нарушать A01 и не заменять данные в БД при seed. Сделай главный экран с ближайшей парой, дедлайном и активной заявкой; фиксируй тесты и экранные доказательства.»  
Критерии: D-Q03–D-Q07 PASS с логом; сохранение после рестарта.

ЗАДАНИЕ A03 — UI/UX (P0, владелец: дизайнер, отдельные шаблоны/стили, после фиксации маршрутов)  
«Разработай единый светлый, спокойный, современный интерфейс на Django Templates, не имитирующий официальный бренд МГИМО. Пять пунктов навигации “Сегодня / Расписание / Учёба / Заявки / Профиль”, уведомления в шапке. Первое действие на 360 px для ключевых сценариев без горизонтального скролла. Для каждого экрана покажи состояния data/empty/loading/error (серверные шаблоны могут показывать честную загрузку/ошибку, не обязательно SPA). Семантический HTML, явные labels, фокус, контраст; не привязывать успешный исход к внешним CDN. Изменять только templates/ и static/; модель/права не трогать. Приложи скриншоты 360 и 1440 px с датой и commit.»  
Критерии: D-Q08 и отсутствие сломанных маршрутов; дизайнер не правит models.py.

ЗАДАНИЕ A04 — независимый QA / security (P0, владелец: отдельный QA-агент, не автор кода)  
«Проверь приложение в двух изолированных браузерных сессиях и прямыми запросами. GET/POST с ID чужих profiles, grades, requests, documents, notifications должны возвращать 403/404 без содержимого; неавторизованные запросы — redirect/401. Проверь CSRF, статусную эскалацию, секреты и Argon2-хеш, пустой день, перенос, перезапуск БД, повторный seed, 360 px и ошибки форм. Не ставь PASS без фактической команды/видео/лога. Вынеси дефекты с severity, точным URL и шагами.»  
Изменяемые файлы: tests/, evidence/qa/, QA.md только с разрешением владельца. Никакой скрытой правки бизнес-логики.  
Критерии: отчёт по D-Q01–D-Q12; для BLOCKED указана причина.

ЗАДАНИЕ A05 — deploy / submission (P0, владелец: разработчик и капитан)  
«Подготовь Dockerfile/compose, конфигурацию HTTPS, migrate, collectstatic, постоянный том БД, backup/restore, readme запуска и безопасные env example. Без покупки VPS и публикации секретов без капитана. После развёртывания проверь сайт с двух браузеров. Реальный тест из российской сети делает уполномоченный участник; без него D-Q10 \= NOT RUN. Собери версию релиза, commit hash, QA, скриншоты, историю промптов и текст для жюри без вымышленных этапов.»  
Критерии: публичный URL, работоспособность из РФ, документ submission, назначенная поддержка до итогов.

Правила параллельности  
Можно параллельно готовить UI\_SPEC/шаблоны и QA-кейсы пока программист создаёт схему; нельзя параллельно менять models, urls, settings, migrations и базовый README. Все новые решения — одна запись ADR с датой и владельцем.
