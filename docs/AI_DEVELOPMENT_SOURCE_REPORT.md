Исходный отчёт об использовании ИИ-агентов для MGIMO AI Challenge 2026 (направление «Вайб-кодинг»).

## 1. Краткое резюме

Проект разработан за 6 дней (17–22 ноября 2026) силами двух основных агентов под управлением человека-капитана. **Hermes Agent** (модель MiniMax-M2.5-NVFP4) был основным разработчиком: по подготовленным человеком заданиям A01–A04 он создал весь Django-монолит — авторизацию, изоляцию двух демо-студентов, расписание, оценки, заявки, уведомления, служебную админку, — а затем в режиме автономных «AFK-проходов» сам находил и реализовывал улучшения (производительность, Docker-обвязка, защита от перебора паролей, отсчёт до пары). Итог — 147 интеграционных тестов, растущих с 14 по мере разработки, и деплой на VPS.

**OpenAI Codex CLI** использовался как независимый ревьюер и дизайнер: он написал документ UI/UX-ревью, по которому затем сам же исправил код с двумя своими субагентами; выполнил редизайн экрана «Сегодня»; провёл конкурсное ревью диапазона коммитов с планом P0/P1, который был полностью реализован в тот же вечер. На раннем этапе (10–17.11) планирование и подготовка заданий велись в ChatGPT (GPT-6) — эти документы стали «техническим заданием» для Hermes.

Ключевой паттерн работы: человек формулирует задачу или ревью → агент реализует → отдельный субагент или второй инструмент проверяет независимо → человек принимает решения по спорным пунктам. Ни один коммит не попал в репозиторий без проверки тестами; все 106 коммитов подписаны человеком, агенты работали в ветках и worktree-изоляции.

## 4. Наиболее показательные кейсы

### Кейс 1. Первый вертикальный срез по готовому ТЗ (A01) — 17.11
- **Агент:** Hermes. **Задача:** по заданию A01 из docs/AI_TASKS.md создать работающую вертикаль «вход → расписание → заявка → сохранение → изоляция».

## 5. Ошибки и улучшения

### 5.1. Галлюцинации субагента-ревьюера (19.11)
- **Проблема:** субагент-ревьюер формулировок утверждал, что строк «Предстоящих занятий нет» и кнопки «Новая справка» в коде нет, а файл request_sample.html отсутствует.

- **Коррекция:** вердикты по этим пунктам отброшены, приняты только подтверждённые; одна правка отклонена по существу с обоснованием.
- **Итог:** в продукт попали только проверенные правки; 28 тестов OK. Подтверждено (PROMPT_LOG D-P007).

### 5.2. Самодельный троттлинг логина → django-axes (21.11)
- **Проблема:** первая версия троттлинга (написана агентом в AFK-проходе) считала и успешные попытки — «5 опечаток блокировали студента»; вторая пропускала без счёта запросы уже вошедшего пользователя — дыра для перебора паролей из-под сессии.
- **Коррекция:** человек выбрал замену на django-axes; агент корректно настроил комбинированный параметр блокировки (вложенный список — иначе блокировка по IP заденет всех студентов с одного IP) и переписал тесты под семантику axes.
- **Итог:** живая проверка «fail5 → 429», 88 тестов OK, решение зафиксировано в D-ADR-19. Подтверждено.

### 5.3. Регрессии редизайна, найденные тройным ревью (22.11)
- **Проблема:** портирование дизайн-системы сломало тёмную тему (мост переменных `--fx-*` определён на `:root`, а тема вешается классом на body — контраст 1.3–1.8:1 вместо 4.5:1 на 16 страницах) и контраст акцента (3.97:1 у ссылок).
- **Обнаружение:** три независимых read-only ревьюера (главный + два interface-review, второй с фокусом на доступность), контраст посчитан программой по WCAG-формуле.
- **Коррекция:** мост `--fx-*` перенесён на body, акцент затемнён до #0072af, возвращено подчёркивание ссылок, исправлен мобильный баг с backdrop-filter и fixed-навигацией.
- **Итог:** коммиты 7bfef59, d1ee2c1 в worktree; доступность по 22 шаблонам без нарушений. Подтверждено (в master эти фиксы не переносились — см. раздел 7).
