11 UI\_SPEC — Деканат · интерфейс без нового дизайн-проекта  
17.11.2026 · краткий UX-контракт для Django Templates. Сценарии основаны на PRD/отчёте Product Owner; это план, не реализованные макеты.

1\. Позиционирование  
Приложение отвечает «что мне делать сейчас?». Шапка показывает название «Деканат» и постоянную заметную подпись «Конкурсный концепт. Не является официальным сервисом вуза. Все данные вымышлены». Никакого официального логотипа и фейковых ссылок на реальные системы вуза.  
Визуально: чистый светлый интерфейс, тёмно-синий текст/акценты, карточки с небольшими радиусами, ясная типографика, аккуратные разделители. Избегать декоративного шума, тяжёлой анимации, сложных графиков и зависимостей от внешних CDN.

2\. Навигация  
Пять понятных разделов: Сегодня · Расписание · Учёба · Заявки · Профиль.  
Уведомления и новости — колокольчик в шапке. На мобильных нижняя навигация; на широких экранах боковая/верхняя навигация. Выбранный раздел явно помечен. Ключевое действие доступно за 1–2 перехода.  
Вход/выход отдельный безопасный сценарий, выход не сохраняет сессию.

3\. Экран «Сегодня» (главный)  
Первый экран: приветствие с вымышленным именем, дата по Москве, группа.  
Блок 1: ближайшее занятие, время, предмет, преподаватель, аудитория. При переносе показать было → стало, кем/когда изменено, причина.  
Блок 2: ближайшие дедлайны с датой (не писать «завтра», если дата вычислена неправильно).  
Блок 3: оценки/задолженности, только имеющиеся данные; пустая оценка \= «Преподаватель ещё не внёс».  
Блок 4: активная заявка и текущий статус, ссылка в её детали.  
При отсутствии пар: «Сегодня занятий нет», при наличии данных — ближайшая следующая пара. Честная пустота важнее фиктивного успеха.

4\. Экран «Расписание»  
Сегменты «Сегодня» и «Неделя». Персональный контекст берётся из профиля, не выбирается заново. Видно основную и языковую группу, можно быстро вернуться к своему расписанию. Каждый урок: дисциплина, начало/конец, аудитория, преподаватель; перенос содержит старые и новые значения и отметку времени. На 360 px — вертикальные карточки по дням без таблицы шире экрана.

5\. Экран «Учёба»  
Дисциплины → оценки/зачёты → информация о сессии. Оценка может быть отсутствующей, незавершённой или готовой; любой статус словами, не только цветом. Если есть дата источника — вывести её честно как время обновления демонстрационных данных; нельзя писать «только что», если данные seed от другой даты.  
Калькулятор «до 4 и до 5» только после P0: пороги и веса задаются в демоданных дисциплины, если не заданы — «Схема оценивания не задана». Не придумывать официальный рейтинг.

6\. Экран «Заявки»  
Список со статусом, типом, датой и номером; «Заказать справку», «Подать заявление». Форма с минимальными полями, явными label, inline-ошибками и проверкой на сервере. После отправки показать номер, статус «Подана» и срок только если он обоснован демоправилом. Детали: хронология статусов, причина отклонения, защищённый документ-образец. Студент не имеет кнопки изменения статуса.  
Для staff отдельный интерфейс Django Admin с оговорёнными правами, не официальный «кабинет деканата».

7\. Уведомления  
Одна лента: объявления, сроки, переносы, статус заявок. Разделять личные и общие записи. Прочитано/не прочитано хранить серверно. Переходы ведут только к разрешённому объекту; чужой URL — отказ. Не делать email/push, пока ядро не проверено.

8\. Состояния и доступность  
У каждой страницы четыре сценария: загруженные данные, осмысленная пустота, загрузка (если применимо), сбой/повтор. Ни один интерфейс не показывает fake-success до подтверждения DB commit.  
360, 390, 768, 1440 px: без горизонтальной прокрутки страницы, поля не закрыты клавиатурой, таблицы преобразованы в карточки, размер кнопок удобен для касания.  
Семантический HTML, alt/aria только по необходимости, label for input, видимый focus, контраст, ошибки не только красным цветом, сообщения об успехе/ошибке доступны скринридеру.  
Иконки — локальные/разрешённые по лицензии. Без официальной айдентики МГИМО.

9\. Demo-flow для жюри  
А: вход → главный экран → персональная пара с переносом → оценки/сессия → подача справки → номер/статус → обновление и повторный вход.  
B: отдельный вход → другие занятия/оценки → проверка чужого request URL \= 404\. Staff: изменение статуса → событие и уведомление A → открытие документа-образца.  
Записывать экран и версии только после реализации. Скриншоты рисованного концепта не выдавать за продукт.

10\. Определение готовности UI  
Основной пользователь без подсказки находит пару/заявку/дедлайн. На 360 px все обязательные формы отправляются и ошибки читаются. Два пользователя не видят чужой контент, даже если вручную меняют адрес. Проход по D-Q08 зафиксирован реальными проверками.
