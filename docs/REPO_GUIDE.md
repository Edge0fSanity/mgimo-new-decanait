2\. Как переносить Google Drive → docs/  
В Drive сейчас 8 основных нативных Google Docs, новые техдокументы и несколько DOCX-отчётов. Это не готовые .md файлы: простое копирование ссылок или переименование .docx в .md не работает.  
Перед первой разработкой экспортировать каждый выбранный Doc в текст/Markdown, проверить заголовки, таблицы, списки, номера D-R/D-Q и ссылки; положить читаемые UTF-8 .md в docs/. Оригиналы остаются на Drive. В начале каждого Markdown: source URL, дата экспорта, версия/modifiedTime при наличии.  
Отчёт Product Owner и исследовательский DOCX — источники в Drive; ссылки добавить в docs/sources/README.md. Если копируете DOCX в Git — убедиться, что нет персональных ответов/контактов и что публикация допустима; по умолчанию не включать.  
AGENTS.md скопировать в корень репозитория. В docs/ можно оставить копию для документации, но владелец — одна версия; не редактировать две копии независимо.  
После импорта Git — источник истины для кода, тестов и фактических evidence; Google Docs остаётся источником продуктовых/организационных документов. Синхронизация только осознанная, по diff и через одного ответственного. Конфликт версий не решать бездумной перезаписью.

3\. Первые команды разработки (пример, не доказательство выполнения)  
Создать новый пустой репозиторий, импортировать проверенные docs, затем Django 5.2 LTS (актуальный патч), Python 3.12. Использовать uv или иной один менеджер зависимостей, фиксировать lock-файл.  
Выполнить локально: установка зависимостей → python manage.py check → python manage.py migrate → безопасная генерация двух демо-аккаунтов через management command → python manage.py test или pytest → python manage.py runserver.  
Пароли демо не прошивать в seed или в Git. Генерировать через секреты окружения / интерактивный ввод на стороне владельца; хранить только хеши. По завершении проверки секреты не печатать в логах и не сохранять в prompts.  
Пример .env.example: DJANGO\_SECRET\_KEY=CHANGE\_ME; DJANGO\_DEBUG=False; DJANGO\_ALLOWED\_HOSTS=example.invalid; DJANGO\_CSRF\_TRUSTED\_ORIGINS=https\://example.invalid; DJANGO\_DB\_PATH=/data/db.sqlite3; DJANGO\_TIME\_ZONE=Europe/Moscow. Настоящие значения — только env/секреты сервера.  
В .gitignore исключить .env, db.sqlite3, \*.sqlite3, .venv, \_\_pycache\_\_, media с личными документами, .pytest\_cache, coverage, backup, дампы БД и приватные артефакты.

4\. Правило минимального вертикального среза  
Первый PR/коммит должен содержать работающие страницы входа, профиля, расписания и заявки, миграции, seed, тесты A→B и B→A. Нельзя принимать PR только по скриншотам. Сразу сохранять prompt, реальную команду теста, результат, commit hash и краткий changelog.  
До закрытия этого среза не реализовывать калькулятор, офлайн-кеш и кабинет сотрудника.

5\. Выпуск на VPS (план, не выполнено)  
— Проверить провайдера/локацию и тариф с постоянным томом; покупку и публичные права доступа согласовывает капитан.  
— Docker image собирается без секретов; SQLite и файлы в постоянном volume, не внутри образа.  
— Gunicorn обслуживает Django, Caddy — HTTPS и статику. Гарантировать корректный proxy SSL header и Secure cookies.  
— Проверить DEBUG=False, ALLOWED\_HOSTS, CSRF\_TRUSTED\_ORIGINS, SECURITY\_MIDDLEWARE, login rate limiting, collectstatic, python manage.py check \--deploy.  
— Запуск миграций контролируемый; повторный deploy не уничтожает базу; ручной backup и test restore в отдельной среде.  
— В браузере из реальной российской сети без VPN открыть сайт, войти обоими пользователями, проверить полные CSS/JS ресурсы, создать заявку и открыть документ. Зафиксировать устройство/дату/сеть, без секретов.  
— До 28.11 минимум ежедневный ручной smoke, назначить ответственного за сервер и оплату; при переносе объявления итогов продлить поддержку.  
— Не утверждать «проверено из РФ», если проверка была только с машины разработчика вне РФ.

6\. Критерии pull request  
\[ \] Небольшой scope и ссылка на Dxx, D-Rxx.  
\[ \] Миграции применяются к пустой БД и поверх существующей.  
\[ \] Автотесты воспроизводимы, негативный тест IDOR есть для каждого затронутого объекта.  
\[ \] Скриншот или видео actual UI для UX-задач.  
\[ \] Нет новых внешних сервисов без ADR.  
\[ \] Нет секретов и персональных данных в code, git history, логе, вложениях.  
\[ \] PROMPT\_LOG и evidence содержат реальные, не придуманные результаты.  
\[ \] Описание проверки включает exact commit и команды.  
Изменения после релиза требуют smoke и повторного теста безопасности, если затронуты auth, модель или permissions.
