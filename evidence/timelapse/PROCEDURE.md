# Процедура: скриншот сайта на каждом коммите (для timelapse)

Цель — кадры того, как сайт формировался. Один коммит = одна папка
`evidence/timelapse/<короткий хеш>/`, имена файлов `<страница>_<ширина>.png`.

## Шаги

1. Определить «снимаемые» коммиты: только те, где менялся UI или добавлялись
   страницы (A01 `fd5c570`, A02 `f1cb0e4`, A03 `3698955`, далее по списку).
   Технические коммиты (фиксы тестов, документация) пропускаются.
2. Поднять сайт на коммите (не мешая основному серверу на :8000):

       scripts/timelapse_serve.sh <commit> 8801

   Скрипт создаёт worktree в /home/nikita/.hermes/cache/scratch/timelapse/<хеш>/,
   делает migrate + идемпотентный seed с паролями из .secrets/demo_passwords.txt
   и запускает сервер на указанном порту с DJANGO_DEBUG=1 (иначе статика не
   отдаётся). Worktree изолирован: БД и .secrets у него свои.
3. Снять кадры браузером (Chromium через CDP), залогинившись demo_a:
   - 360 px (deviceScaleFactor=2, mobile): `/`, `/schedule/?view=week`,
     `/grades/`, `/requests/`, `/notifications/`, `/profile/`
   - 1440 px: `/`, `/grades/`
   - На каждом кадре проверить `documentElement.scrollWidth == clientWidth`.
   - Копировать каждый снимок сразу: capture_screenshot() пишет всегда в один
     и тот же tmp-путь — копируй после каждого кадра, иначе перезапишется.
4. Остановить сервер (kill pid), удалить worktree:
   `git worktree remove --force <worktree>`.
5. Пометить в evidence/prompts/ соответствующего этапа, что кадры сняты на
   этом коммите; для ретроспективных кадров (снятых позже на старом коммите)
   писать «реконструкция, снято <дата>».
6. Закоммитить папку кадров.

## Питфоллы

- Сервер без DJANGO_DEBUG отдаёт 404 на /static/ — кадры будут без стилей.
- Страница логина нужна только для входа; в кадры её не включать.
- Пароли брать из .secrets/demo_passwords.txt, в кадры и логи не писать.
- Не снимать на основном чекауте с переключением коммитов — рабочее дерево
  должно оставаться на master; для старых коммитов только worktree.
